== Asset service

So far, the site is made up of dynamic HTML and images. Static assets, such as CSS and JavaScript files, are served by the {xp-docs}/{xp-docs-version}/runtime/engines/asset-service[asset service]. Every file you place in the `src/main/resources/assets` folder is available at a URL.

Your app already includes a sample CSS file: `src/main/resources/assets/mvp.css`.

== Perfect cache

In production, XP serves every asset with cache headers that let browsers, proxies, and CDNs cache it, without ever having to download it again.

The generated asset URL contains a prefix based on a signature of the files in the app. The signature changes with every new version of the app. The `assetUrl()` function uses this signature when generating the URL, so clients always get the most recent version.

NOTE: In development mode, which you are using now, cache headers are deactivated.

== Static Assets library

With advanced build tools, assets may be split into chunks and served incrementally. Changing the URL of every asset on each deployment is then no longer optimal. The https://market.enonic.com/vendors/enonic/lib-static[Static Assets library] (`lib-static`) gives you full control over how assets are served.

The library is bundled with your app, and serves the files in the `src/main/resources/static` folder. To make the URLs immutable, a content hash is added to each file name at build time. The hash is generated from the content and location of the file, and only changes when they do. The browser can then cache the asset indefinitely, and load it from the cache every time it meets the URL.
