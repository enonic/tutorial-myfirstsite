In this chapter, you'll install the Enonic CLI, start a local Enonic XP sandbox, and create and deploy the app you'll build on for the rest of the tutorial.

== Enonic CLI

The Enonic CLI (Command Line Interface) manages local XP instances, creates projects from starters, and builds and deploys your apps.

=== Task: Install the CLI

. *Install the command-line tool* - If you have `npm` on your machine, run:
+
[source,shell]
----
npm install -g @enonic/cli
----
+
If not, there are https://developer.enonic.com/start[alternative ways to install the Enonic CLI].

. *Verify the installation* - Run `enonic -v`.
The command prints the version of the installed CLI.

TIP: Run `enonic` without arguments to list the available commands, and `enonic latest` to check for a newer version of the CLI.

== Sandbox

A _sandbox_ is a local developer instance of Enonic XP. Each sandbox is isolated from the others, with its own data and configuration, and can run a different version of XP.

=== Task: Create a sandbox

. *Create and start the sandbox* - Run this command in your terminal:
+
[source,shell,{subs}]
----
enonic sandbox create {sandbox-name} -t essentials -v {xp-version} -f
----
+
This creates a sandbox called `{sandbox-name}` running Enonic XP {xp-version}, installs the applications in the `essentials` template, including Content Studio, and starts the sandbox.

. *Verify that XP is running* - Wait until the terminal stops printing new log lines, then open {xp-url}[{xp-url}] in your browser. You should see the XP boot page:
+
image::xp-welcome.png["The XP boot page with the title Welcome to the Enonic SDK and a Log In as Guest button", width=1440]

Leave the sandbox running in this terminal, and open a new terminal for the next task.

== App

Everything you build in this tutorial lives in an Enonic app. You'll create it from the `{starter-repo}` starter, which gives you an empty app with TypeScript and a build setup.

=== Task: Create the app

. *Create the project* - From the folder where you keep your projects, run:
+
[source,shell,{subs}]
----
enonic project create {app-name-full} -r {starter-repo} -s {sandbox-name} -d {app-dir} -f
----
+
The command creates the folder `{app-dir}`, gives the app the name `{app-name-full}`, and links the project to the `{sandbox-name}` sandbox.
+
IMPORTANT: Use the app name `{app-name-full}`. The sample content you'll add in the next chapter refers to content types by this name.

. *Give the app a title* - The title is what Content Studio shows when you pick the app. Replace the content of the application descriptor with the following:
+
.src/main/resources/enonic.yaml
[source,yaml,{subs}]
----
kind: "Application"
title: "{app-title}"
description: "A site built with the Enonic Site Framework"
vendorName: "Acme Inc"
vendorUrl: "https://example.com"
----

The parts of the project you'll work with are:

[source,text]
----
build.gradle <1>
src/main/resources/
  enonic.yaml <2>
  assets/ <3>
  cms/ <4>
    cms.yaml
    content-types/
    layouts/
    pages/
    parts/
----

<1> The build file, where you add the libraries the app uses
<2> The application descriptor
<3> Static assets, such as CSS files
<4> Everything related to the CMS: content types and the components that render them

=== Task: Build and deploy the app

. *Start dev mode* - Run these commands in the new terminal:
+
[source,shell,{subs}]
----
cd {app-dir}
enonic dev
----
+
`enonic dev` builds the app, deploys it to the sandbox, and then watches the source files. Each time you save a file, the app is rebuilt and redeployed.

. *Verify the build* - The first build downloads dependencies and takes a little while. When it is done, the terminal prints:
+
[source,text]
----
BUILD SUCCESSFUL
Waiting for changes to input files...
----

Leave `enonic dev` running. When a later chapter asks you to restart it, press kbd:[Ctrl+C] and run `enonic dev` again.

=== Task: Log in to XP admin

. *Log in* - On the {xp-url}[XP boot page], click btn:[Log In as Guest].

. *Verify the result* - You are now on the XP admin home page, with a tile for each installed admin tool, including Applications and Content Studio:
+
image::xp-admin.jpg["The XP admin home page with tiles for Dashboard, Applications, Content Studio, Data toolbox and Users", width=1440]
