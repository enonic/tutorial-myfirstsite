On this page, you'll make your site answer at a URL that has no content behind it, by mapping the URL to a function in your app.

This page requires the result of <<../go-online#,chapter 9>>, as described in <<../advanced#,Advanced features>>.

== Mappings

Every page you have rendered so far belongs to a content item: the site service finds the content at the requested path, and renders its page. Some URLs are different. Files such as `robots.txt`, `sitemap.xml`, and `llms.txt` have a fixed address at the root of a site, and there is no content item to render.

A _mapping_ binds a URL pattern to a function in your app. Mappings are listed in the site descriptor, and the site service checks them before it starts rendering a page. When a pattern matches, your function handles the request, and no page is rendered.

The example here is https://llmstxt.org[llms.txt], a proposed convention for telling AI tools what a site contains, written as Markdown.

The file is made from the content each time it is requested. Publish a new country, and it shows up in the list.

== When to use a mapping

A mapping is the right tool when the URL is decided for you, as it is for `llms.txt`. When you can choose the URL yourself, an <<apis#,API>> is usually a better fit.

Mappings can do more than this page shows. A mapping can match content instead of a URL, for instance all content of one type, and it can point to a filter that runs before and after the rendering instead of replacing it.
